Factory Inventory Management System

A demo application with a Vue 3 single-page frontend and a FastAPI backend that serves in-memory mock data loaded from JSON files. There is no database.

System architecture

Two local processes. The browser talks directly to the API; CORS is open.

Data flow

How a filter change on the dashboard becomes updated numbers on screen.

  1. User changes a filter. FilterBar updates the shared refs in useFilters.js (Time Period, Warehouse, Category, Order Status). Every view reads the same singleton.
  2. View builds the request. getCurrentFilters() maps Time Period to the API's month param, and api.js drops any param equal to 'all'.
  3. axios sends a GET to http://localhost:8001/api/....
  4. FastAPI route filters in memory. apply_filters and filter_by_month run over the lists loaded by mock_data.py. Month accepts 2025-01 or Q1-2025 and matches order_date, so it only affects orders and the dashboard.
  5. Pydantic validates the response and FastAPI returns JSON.
  6. The view stores raw data in refs (allOrders, inventoryItems) and derives totals, charts and tables in computed properties. Strings come from useI18n and currency from the active locale.

Key design notes

No persistence

Data is loaded once at import. Edits to the JSON files require a backend restart.

Singleton filters

One module-level filter state is shared across all views, so selections follow the user between routes.

Internationalisation

English and Japanese locale files; the locale is stored in localStorage and also selects the currency.

Mock auth

useAuth.js supplies a fixed, language-aware user. There is no real authentication.
